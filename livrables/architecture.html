Robot SUMO : architecture implémentée dans le FPGA

Cours FPGA/VHDL MKX 3A, IMT Mines Alès. Carte Terasic DE0-Nano (Intel Cyclone IV E EP4CE22F17C6N), Quartus Prime Lite 20.1.

1. Fonctions réalisées

  • Démarrage : à la mise sous tension (et après chaque appui sur BP1), reset de 1 ms puis envoi au PC du message Robot PRET !\n\r par la liaison série (9600 bauds, 8 bits, sans parité, 1 stop), puis attente d'une commande.
  • Choix du mode par le PC : c = combat SUMO, s = suiveur de ligne (course EMA). Les autres caractères sont ignorés ; le mode peut être changé à tout moment.
  • Combat SUMO : machine à états imposée (§6.3 du cahier des charges) : attente de 5 s, recherche de l'adversaire en tournant sur place, attaque, évitement de la bordure du Dohyo, arrêt définitif si la batterie est vide.
  • Suiveur de ligne : suivi de la ligne noire par 5 capteurs de sol, demi-tour à chaque extrémité du circuit ouvert, arrêt après 2 allers/retours (4 extrémités).
  • Batterie : LED7 commandée en PWM, rapport cyclique proportionnel à la tension (100 % à 9 V, 10 % à 7,2 V) ; sous 7,2 V pendant 1 s, LED7 clignote à 1 Hz et les moteurs sont arrêtés.
  • Contraintes respectées : circuit de reset de 1 ms (§6.1), horloge système de 500 kHz issue d'un diviseur (§6.2), PWM moteurs à 5 kHz (§6), émetteur et récepteur série fournis (UART_TX, UART_RX, §5), utilisés sans modification de leur logique.

2. Architecture générale

Figure 1 : blocs et liaisons de robot_sumo_top. En jaune, l'unité de contrôle (fsm_combat, suiveur_ligne, message_demarrage, selection_mode) ; en blanc, le chemin de données (adc_ctrl est l'IP « ADC Controller for DE-series Boards » du catalogue IP de Quartus, la même qu'au TP2). 5. Mise en œuvre

5.1 Compiler

  1. Ouvrir quartus/robot_sumo.qpf dans Quartus Prime Lite 20.1.
  2. Lancer la compilation complète (flèche verte). Résultat attendu : 0 erreur ; 3 avertissements génériques (intensité de sortie non précisée, rappel 3,3 V, LogicLock).
  3. Pour une configuration persistante, le fichier robot_sumo.jic est fourni (sinon : File > Convert Programming Files, EPCS64, SFL EP4CE22, comme dans Program_eeprom_de0.pdf).

5.2 Programmer et tester

  1. Vérifier d'abord le robot avec SumoTests.jic (capteurs, moteurs, batterie, BP1) comme le conseille le sujet.
  2. Programmer la DE0-Nano par l'USB-Blaster (Tools > Programmer, mode JTAG) avec robot_sumo.jic.
  3. Relier le câble mini USB du module USB/série au PC ; ouvrir PuTTY sur le port COM correspondant : 9600 bauds, 8 bits, pas de parité, 1 stop, pas de contrôle de flux (ConfigDePutty.pdf).
  4. Mettre le robot sous tension : Robot PRET ! s'affiche ; LED6 et LED5 éteintes (attente).
  5. Taper c : LED5 allumée, combat après 5 s. Taper s : LED6 allumée, suivi de ligne immédiat. BP1 : reset (nouveau message, retour en attente).

6. Vérification réalisée

Chaque entité a un banc de test auto-vérifiant (dossier tb/, simulateur ModelSim, assertions, chien de garde) qui affiche TEST OK seulement si tous les contrôles passent. Le code synthétisable est en VHDL-93 (réglage du projet Quartus) et la compilation ne produit aucun latch.

Le banc système simule le robot entier : message de démarrage reçu par un PC simulé, commande c, recherche, attaque (des deux côtés et d'un seul), recul sur la bordure, batterie vide, reset par BP1, commande s, suivi de ligne (tout droit, virage doux, pivot), extrémité de ligne et demi-tour, puis batterie vide en mode suiveur. Pour rejouer tous les bancs : ouvrir ModelSim (livré avec Quartus), File > Change Directory vers le dossier sim/, puis taper do simuler.do dans la console. Le script compile l'IP de l'ADC, les sources et les bancs, lance chaque banc et affiche un bilan (OK / ECHEC).
